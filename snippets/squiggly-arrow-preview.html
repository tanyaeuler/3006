If it isn't showing up

Nearly always the page builder, not the arrow. Work down this list.

  1. The block was pasted into a rich-text widget. Elementor's Text Editor, the WordPress paragraph block and Squarespace's text block all strip <style> and <script> on save. Use a Custom HTML / Code widget instead — or use the self-contained SVG below, which needs neither.
  2. Only part of the block made it across. The <div>, the <style> and the <script> are one unit. The svg on its own has nothing to size or animate it.
  3. A theme rule is overriding it. Inspect the path and look for stroke-dashoffset: 100 that never reaches 0, or a stroke: none from a global svg rule. A theme that sets svg { fill: currentColor } is harmless; one that sets stroke is not.
  4. The row it sits in has no height. An empty flex or grid cell can collapse to 0 and clip the arrow away. Give the wrapper a min-height of about 130px and check overflow isn't hidden on the column.
  5. It's inside a tab, accordion or slider. Content injected after page load can miss the scroll trigger. The updated snippet re-scans on load for exactly this, but the SVG version sidesteps it entirely.

Whatever the cause, the arrow no longer disappears when something is stripped: no script means it draws on page load instead, and no styles at all still leaves a static arrow at the right size and colour.

Two ways to drop it in

Both are in the repo. Start with the SVG if the HTML block gave you trouble.

1 · Self-contained SVG — the safe one

The animation lives inside the SVG, so it survives builders that strip <style> and <script>. Paste snippets/squiggly-arrow.svg inline, or upload it to your media library and place it as an ordinary image. It animates once on page load rather than on scroll — the one thing it gives up. 

<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 220 120" width="220" height="120"
     role="img" aria-label="Arrow pointing to the list on the right">
  <g fill="none" stroke="#4f9d8a" stroke-width="5"
     stroke-linecap="round" stroke-linejoin="round">
    <animateTransform attributeName="transform" type="translate"
                      values="0 0; 6 -6; 0 0" keyTimes="0; 0.5; 1"
                      dur="3.2s" begin="2.2s" repeatCount="indefinite" />
    <path pathLength="100" stroke-dasharray="100" stroke-dashoffset="0"
          d="M 6 97 C 26 74, 47 117, 68 93 S 106 68, 126 92
             C 146 110, 158 86, 168 63 C 178 43, 187 31, 197 21">
      <animate attributeName="stroke-dashoffset" values="100; 0" keyTimes="0; 1"
               calcMode="spline" keySplines="0.65 0.05 0.36 1"
               begin="0.15s" dur="1.6s" fill="freeze" />
      <set attributeName="stroke-dashoffset" to="100" begin="0s" end="0.15s" />
    </path>
    <path pathLength="100" stroke-dasharray="100" stroke-dashoffset="0"
          d="M 177 28 L 197 21 L 191 41">
      <animate attributeName="stroke-dashoffset" values="100; 0" keyTimes="0; 1"
               calcMode="spline" keySplines="0.4 0 0.2 1"
               begin="1.46s" dur="0.45s" fill="freeze" />
      <set attributeName="stroke-dashoffset" to="100" begin="0s" end="1.46s" />
    </path>
  </g>
</svg>

To recolour it, change both stroke="#4f9d8a" values. Nothing else.

2 · HTML block — draws on scroll

snippets/squiggly-arrow.html, pasted whole into a Custom HTML widget. Holds until the arrow is scrolled into view, then draws and drifts. The stroke and stroke-width attributes on the svg are the no-CSS fallback — keep them in step with the custom properties if you recolour it. 

<div class="squiggly-arrow">
  <svg viewBox="0 0 220 120" width="220" height="120" role="img"
       aria-label="Arrow pointing to the list on the right"
       fill="none" stroke="#4f9d8a" stroke-width="5"
       stroke-linecap="round" stroke-linejoin="round">
    <path class="sa-tail" pathLength="100" d="M 6 97 C 26 74, …" />
    <path class="sa-head" pathLength="100" d="M 177 28 L 197 21 L 191 41" />
  </svg>
</div>

Dials

On the HTML version, everything is a CSS custom property on .squiggly-arrow.

  • --sa-color — line colour. Also update the svg's stroke attribute so the no-CSS fallback matches.
  • --sa-width — overall width. Height follows the 11:6 aspect ratio automatically.
  • --sa-stroke — line thickness, in viewBox units (5 reads like a marker at 220px wide).
  • --sa-speed — how long the squiggle takes to draw. The arrowhead lands at 82% of that.
  • --sa-delay — pause before the draw starts.
  • snippets/squiggly-arrow.svg — self-animating SVG, no CSS or JS required.
  • snippets/squiggly-arrow.html — HTML block with the scroll trigger and the CSS dials.
  • src/components/ui/SquigglyArrow.jsx — React component with color, width, strokeWidth, duration, drift and flip props.

Behaviour worth knowing

  • In the HTML version the draw fires once, when 40% of the arrow is in view — so it isn't already finished by the time a visitor scrolls down to it. An arrow that is already on screen at load plays straight away rather than waiting for a scroll that never comes.
  • Under prefers-reduced-motion the finished arrow renders instantly with no drawing and no drift.
  • Below 768px the cards stack under the copy, so the snippet flips the arrow vertically to point down-right instead. Drop that media query if your layout differs. The flip has to sit on the container, not the svg — a CSS animation overrides an inline transform, so the drift would cancel it out.
  • The SVG carries an aria-label; if the arrow is purely decorative next to a heading that already says "take a look below", swap it for aria-hidden="true".
