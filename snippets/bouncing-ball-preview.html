A ball that lays its own track

The ball bounces up and to the right, and the dashed arc appears behind it as it goes — nothing is drawn ahead of where the ball has been. It settles mid-flight at the top right, which is exactly the static graphic you supplied.

The animation

Two bounces, a squash at each impact, then a slow hover once it lands.

Two ways to drop it in

Same graphic, different plumbing. Start with the SVG.

1 · Self-contained SVG — the safe one

snippets/bouncing-ball.svg. The animation is inside the SVG, so it needs no CSS and no JavaScript and survives a builder that strips style and script tags. Paste it inline, or upload it to your media library and place it as an ordinary image. It runs once on page load rather than on scroll — the one thing it gives up. To recolour, change the two #4f4f4f values.

2 · HTML block — runs on scroll

snippets/bouncing-ball.html, pasted whole into a Custom HTML or Code widget. It holds until the graphic is 35% in view, so a visitor sees the bounce happen rather than arriving after it finished.

How the reveal works

Worth knowing before you retime anything.

The dashed arc is drawn in full, then hidden behind a mask. Inside that mask, a thick white stroke sweeps along the same path — as it advances it uncovers the dashes underneath. Butt caps on the sweep put its leading edge exactly at the ball's centre; a round cap would run half a stroke-width ahead and reveal dashes the ball hasn't reached yet.

The sweep and the ball are two separate animations that have to agree, so both use the same keyframe stops — 25% and 77.08% are the two bounces, the others the apexes and mid-flight points — and the same easing pairs: slow into each apex, quick into each bounce. Retime one and you must retime the other identically, or the dashes drift ahead of the ball. 

/* the two must stay in step */
25%    { stroke-dashoffset: 1757; }   /* sweep: first bounce  */
25%    { offset-distance: 21.05%; }   /* ball:  first bounce  */

In the SVG version the same numbers appear as keyTimes with values on the mask and keyPoints on the motion.

Behaviour worth knowing

  • Under prefers-reduced-motion the finished graphic renders instantly — no bounce, no hover.
  • The graphic scales to its container's width; the ball and dashes scale with it. --bx-max-width stops it getting silly on a wide screen.
  • There is deliberate space below the arc: at each bounce the ball dips a radius below the dashes, and without that room it would be clipped. Your static reference needed no such margin.
  • The svg origin is the ball's landing point, not the top left. That is what lets the ball sit in the right place before any animation has been applied — and it is why the coordinates are negative.
  • Nothing in either file mentions style or script tags in a comment any more. A sanitiser matching those tags with a regex will happily eat from a mention in a comment through to the real closing tag, taking the graphic with it.
